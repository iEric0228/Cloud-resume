---
name: Cloud Resume frontend build pipeline
description: How the Eric Chiu Cloud Resume site's frontend is built and deployed, and why frontend/ must not be edited by hand.
---

The static site under `frontend/` is a **build artifact**, not source. It is produced by `vite build` (outDir `../frontend`) from the React app in `web/`. It is gitignored (`/frontend/` in `.gitignore`) and gets regenerated by `scripts/publish-frontend.sh` on every deploy.

**Why:** the project was redesigned from a hand-written static HTML/CSS/JS site into a React + Tailwind + Framer Motion app per an explicit user request for a Stripe/Linear/Vercel-style premium aesthetic. The old deploy scripts sed-replaced an API URL placeholder directly into specific static files (`utils/visitor-counter.js`, `index.html`); that approach doesn't survive a hashed Vite build, so the API URL now lives in an unhashed `web/public/config.js` (copied verbatim into the build), and `publish-frontend.sh` sed-replaces the placeholder there instead.

**How to apply:** any future edit to the resume/portfolio content or design must happen in `web/src/` (components) or `web/src/data/` (copy/content), never in `frontend/` directly — those edits will be silently wiped on the next build. `web/public/resume.html` and `web/public/config.js` are the exception: they are source files copied as-is by Vite, and are the only things under a `public/` directory not gitignored (the repo's `.gitignore` blanket-ignores `public/` for other frameworks, with an explicit `!web/public/` carve-out).
