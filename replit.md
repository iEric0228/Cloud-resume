# Cloud Resume — Eric Chiu

## Overview
A serverless personal resume/portfolio site demonstrating cloud engineering skills, aimed at DevOps / Cloud / SRE / Support Engineer roles.

- **Frontend** (`web/`): React 18 + Vite + Tailwind CSS + Framer Motion + lucide-react. Dark, minimal, Stripe/Linear/Vercel-inspired design. Source of truth for the site.
- **Build output** (`frontend/`): generated by `vite build` (outDir `../frontend`). Not committed — treat it as a build artifact, like `dist/`.
- **Backend** (`backend/lambda/`): Python Lambda behind API Gateway, atomically increments a visitor counter in DynamoDB.
- **Infrastructure** (`infrastructure/`): Terraform, modular by environment (`dev`, `prod`) — S3 + CloudFront + Route 53 + ACM for the static site, API Gateway + Lambda + DynamoDB for the counter.
- **Deploy**: GitHub Actions (`.github/workflows/`) runs Terraform, then `scripts/publish-frontend.sh`, which builds the React app, injects the live API URL into `frontend/config.js`, syncs `frontend/` to S3, and invalidates CloudFront. AWS deployment is out of scope for the Replit environment — Replit is used for local development/preview only.

## Running in Replit
- Workflow **Start application** runs `npm --prefix web run dev` (Vite dev server on port 5000) — this is what the Replit preview pane shows.
- The visitor counter calls a public AWS API Gateway endpoint directly from the browser, so it works in the Replit preview too (no local backend needed).
- `web/public/config.js` holds the API URL used at runtime; in production the deploy script replaces the `REPLACE_WITH_API_URL` placeholder in the *built* `frontend/config.js` — the source file in `web/public/` is never edited.
- `web/public/resume.html` is a printable résumé (linked from the nav/hero); it is copied as-is into the build output.

## Editing the site
- Copy/content: `web/src/data/profile.js`, `projects.js`, `stack.js`.
- Sections: `web/src/components/*.jsx`, composed in `web/src/App.jsx`.
- Styling tokens (colors, radii, shadows): `web/tailwind.config.js` and `web/src/index.css`.
- Project cards currently link their GitHub button to the profile (`github.com/iEric0228`) rather than per-repo URLs — add real repo links in `web/src/data/projects.js` (`github` field) when available.
